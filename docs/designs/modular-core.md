## 目标与已确认前提

- 用户选择“我自己长期使用，优先稳定和可控”，并要求“高内聚、低耦合”。
- 单机、BSC、现有钱包接口；业务目标是每项目累计本金最多 1.2 USDT 等值，gas 单列。第一阶段实际保留“钱包 + 铸造合约”账本键，不能证明同一业务项目多个合约的聚合上限；项目身份映射与跨合约累计是启用真实铸造前的独立验收条件。
- 同款批量部署、开发者风险、证据缺失均不得因进度或强制名单绕过。
- 重启不重复发单、资金和权限可核对，优先于扫描速度。
- 长期可用 Rust 替换交易核心；先固定边界和回放语义，不进行全库语言重写。
- 本轮只依据仓库与本会话，不做外部方案研究。

## 问题与证据

入口 watch.mjs 同时承担配置、RPC、钱包 CLI、交易生命周期、扫描、策略、通知和定时任务。导入文件即运行；部分测试通过截取源码并放进 VM 才能验证函数。配置向导与运行时的预算限制分散，钱包 CLI 依赖 shell 拼接，多个恢复文件的写入顺序必须靠调用者共同维护。

已有预算、回执、费用、授权清理和持仓投影模块可以复用。它们是已测试的行为基础，不能为了拆文件而丢失。

## 选择与取舍

- 采用 B：模块化单体；先通过显式接口降低耦合，再逐步迁移内部实现。
- 不选 A 作为终点：只整理文件不足以解决状态和副作用混杂。
- 暂不选 C：扫描与执行分进程会增加个人部署成本，进程分离本身也不等于权限隔离。
- 保留当前持久化格式及保守记账口径；数据库迁移是后续独立阶段，需专门的迁移与回滚验证。

## 第一阶段实施范围

1. 建立可正常导入的应用与交易服务，入口只负责启动；导入不得创建文件、启动定时器、联网或调用钱包。
2. 抽离配置校验、RPC、钱包 CLI、金额/状态边界和进程生命周期。安全模块使用窄依赖接口，不读取任意全局变量。
3. 将交易预演、预算、执行、回执、持仓投影与授权恢复放在明确的应用服务中；扫描、策略通过服务调用，不自行拼接钱包执行命令。
4. 将测试改为直接导入真实模块，用注入的 RPC、钱包、时钟和存储测试；保留现有失败、重启、重复提交与清理场景。
5. 扫描和策略中的上游启发式逻辑先保持行为兼容，以独立模块或明确的兼容边界承载。模块化不能被描述成已完成历史风控数据接入。
6. Rust 的未来接口使用 JSON 可表达的数据：地址、链 ID、原始金额十进制字符串、操作 ID、结构化状态/错误及可追踪回执；禁止跨边界使用浮点金额或不可序列化隐式对象。

## 模块边界

- domain：金额、地址、操作状态和边界校验，无 I/O。
- adapters：RPC 和 baw CLI；参数数组调用、统一错误，禁止 shell 拼接。
- application：交易生命周期、审批清理、恢复和风险调用；拥有发送交易的能力。
- discovery / strategy：发现候选、计算动作；通过应用服务执行，不直接发送。
- storage：保留当前 JSON 账本实现，显式提供读写；后续可替换为事务型存储。
- runtime：配置加载、锁、定时器、信号处理、启动/停止；不混入项目筛选条件。

## 实施与运行隔离

- 先将当前本地改动保存为可回滚基线，在隔离工作目录开发。
- 不自动合并远端更新；已知上游更新含策略变化，要另行核对。
- 开发与测试不使用真实钱包签名能力，测试不得提交链上交易。
- 本轮属于资金相关代码切换。准入条件是：既有确定性场景转为直接导入真实交易服务，并通过预算、未知结果、回执、清理、重启及停机测试；这些模拟输入构成本轮必过的离线回放。真实证据脱敏语料用于后续 Rust 对照，不作为本次切换尚未完成的隐含前置条件。
- 生产配置与账本的权威位置固定为当前运行目录的 config.json 和 data/。开发目录使用独立临时数据。切换只替换代码，不搬入开发 data；先确认旧进程退出，再读取停机后的最新生产状态。缺失预期生产文件不能默认为空账本。回滚只回滚代码，继续使用最新账本，不能恢复旧资金快照。
- 停机先停止接收新意图，尚未发送的排队、预演任务不得继续发单。已发送操作等待确认，或保留未定记录、预留预算和清理任务后停止。清理阶段停止时也禁止新增发送并保留待清理记录。所有发送入口检查停机状态；退出前等待在途工作到达可恢复边界，超时也必须保留证据。
- 迁移不改变 1.2U 限额或证据缺失拦截；新的真实铸造仍不得启用。
- 工作区配置、运行状态、钱包信息及运行日志保持本地；本轮不推送到公开 GitHub。

## 验收标准

- 原有预算、回执、权限、费用和恢复测试继续通过。
- 直接导入模块无副作用，核心测试不再截取 watch.mjs 源码执行。
- 配置向导、预检和运行时共用预算/钱包校验规则。
- 同一钱包的交易串行约束、未知结果保留预算、清理失败暂停等行为保持。
- 模拟两次启动、正常停止及重启后恢复；锁不会悄悄失效。覆盖预演后停止、发送结果未知时停止、授权清理中停止，确认重启仅恢复原操作而不重送。
- 用含未完成预算与已执行标记的生产格式样本测试跨版本切换与代码回滚，验证数据根不变、金额与标记连续、缺失预期文件会拦截启动。
- 模块图与实际目录一致，未拆完的兼容逻辑明确列出，不宣称已完成 Rust 迁移或数据库迁移。
