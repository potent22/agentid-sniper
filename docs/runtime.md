# 本地运行与切换

当前验证环境：macOS、Node.js 24、单钱包、BSC。上游 Windows 安装器和多钱包部署没有按此分支验证。

## 日常命令

在正式安装目录运行：

```sh
node --test test/*.test.mjs
node preflight.mjs
node watch.mjs
```

预检只查询钱包和链，不交易。用户取消了历史部署覆盖和 rug 历史作为硬门槛；它们仍在预检中显示为未完成并给出警告。已知黑名单和已观测的同款部署三次依旧拒绝。用户同意暂按每钱包、每铸造合约计 1.2U；同一项目多个合约各自独立计算。

自动兑换暂时被阻止，包括为铸造换币和自动卖币：现有清理流程不能保证发现并撤销 Permit2 的内部授权。无需兑换即可支付的铸造可以继续，标准 ERC20 授权的铸造仍需完成并核实撤销。兑换能力需要独立补全和验证后才能恢复。

首次新安装需要先配置 `config.json`，只允许对没有账本的新目录使用 `node watch.mjs --initialize`。迁移已经运行过的旧版本，先按下文停机核对，再一次性使用 `node watch.mjs --migrate-legacy`。这两个参数都不解除风控。

停止可发送 SIGTERM / SIGINT，或者在正式目录创建 `WATCH_STOP`。移走停止标记后才可重新启动。程序没有本分支配置的后台服务或开机自启。

## 数据和锁

正式配置与 `data/` 始终留在同一安装目录，不能把开发目录的文件复制进去。

- `watch_state.json`：持仓、执行去重标记、费用与扫描状态。
- `project_budget.json`：本金累计与未完成预留。
- `recovery.json`：授权/兑换恢复工作。
- `runtime_manifest.json`：绑定数据根和钱包，登记上述文件必须存在。
- `watch.lock`：原子创建的单实例锁，正常停止后删除。异常退出后保留；核对原进程、未完成交易和账本后才能处理，程序不会盲删旧锁。
- `watch.log`、`watch_heartbeat.txt`：运行日志及心跳；心跳不是交易完成凭据。

停机先关发送入口，最多给在途交易四分钟完成回执/记账，再中断剩余读请求并等待后台任务退出。不确定结果仍保留原哈希、订单号、预算和清理记录；不会为了退出把它标成失败。无法正常收敛时以非零状态退出并保留锁。

## 更新与回滚

1. 在隔离工作目录通过测试，保留旧代码版本。不要把测试配置或 `data/` 合入正式目录。
2. 创建停止标记，等待旧进程退出，确认旧锁清理。核对停机后最新的预算、恢复任务、资产记录与配置；不能使用几分钟前的运行快照替代。
3. 仅替换代码。首次迁移需确认没有丢失的历史账本；若记录表明已有本金而预算文件缺失，停止迁移并核对。
4. 在原安装目录移走停止标记并启动；验证单实例、心跳、账本连续性和风控拒绝状态。
5. 回滚也先停止新进程，只恢复旧代码，继续使用最新账本。不得恢复旧资金快照。旧版本不支持新的锁格式，绝不能在新进程仍运行时启动旧版本。

上游自动更新入口已移除；不会按源文件变化自动热替换。上游新增策略需另行审查合并。

## 验证范围

离线测试直接导入真实模块，注入假 RPC、假钱包与存储故障，覆盖额度、未知结果、回执失败、两次启动、迁移、停机、清理恢复和幂等记账。没有以真实资金验证新代码，也不声称完成 Windows 或 Rust 的验证。
